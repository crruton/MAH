# Процесс: как запустить харнес, который развивается сам

Главная мысль: **модель не учится между сессиями, учится среда — и это видно по цифрам.** Шесть шагов ниже запускают петлю «поймать → заметить → записать → запретить → научить → проверить» ([docs/LOOP.md](docs/LOOP.md)) и доводят её до состояния, когда человек только ревьюит MR с новым барьером.

```
 1. Базовая линия ─► 2. Первые ошибки ─► 3. Петля в команде ─► 4. Пайплайн проверок ─► 5. Замеры ─► 6. Фиксация
                         ▲                                                                   │
                         └──────────────── ./harness.sh evolve каждый день ──────────────────┘
```

Каждый шаг заканчивается строкой **«Теперь держит среда»** — что после него контролирует машина, а не человек.

---

## Шаг 1. Базовая линия: среда, харнес, метрики

**Вход:** машина разработчика с агентом (Claude Code; правила подходят и для OpenCode).

**Действия:**
1. `./harness.sh install` — один раз на машину. Хук `guard.sh`, сборщик ошибок, 5 процессных скиллов работают во всех проектах; в репозитории ничего не копируется.
2. `./harness.sh demo` — 35 атак останавливаются, 16 обычных действий проходят.
3. В каждом проекте — свой `AGENTS.md`: стек, точные команды сборки и тестов, карта кода. Не больше 150 строк.
4. Защитить `main` на сервере: push запрещён всем, merge — мейнтейнерам. Работа идёт в `dev`.
5. `./harness.sh dashboard` — снять нулевую точку: ошибки на 100 вызовов, токены и рубли на сессию, активное время.

**Готово, когда:** `./harness.sh doctor` зелёный, демо проходит, у дашборда есть первая неделя данных.

**Теперь держит среда:** необратимые действия (B05), секреты и токены (B06, B31), обход хуков (B28), ручная правка lock-файлов (B32). Каждая попытка — событие в журнале.

---

## Шаг 2. Первые ошибки: петля рождается

**Вход:** агент ошибся: сломал сборку, прочитал секрет, обошёл запрет, выдумал API, починил тест вместо кода.

**Действия:**
1. Ошибку уже поймал хук, гейт или сборщик упавших вызовов. `./harness.sh evolve .` заводит черновик инцидента в `error.md`; если ошибку заметил человек — `./harness.sh incident . "что случилось"` в течение 24 часов.
2. Агент закрывает инцидент скиллом `error-to-rule`: класс ошибки, а не случай; барьер как можно глубже (ОС > сервер > хук > текст); атака-репро, которая падает до барьера и проходит после.
3. Сообщение барьера говорит агенту, что делать вместо этого; строка в `AGENTS.md` — для следующих сессий.
4. Человек ревьюит MR с барьером (`review/harness-review.md`).

**Готово, когда:** гейт `check-error-log.py` зелёный — у закрытого инцидента есть барьер и репро.

**Теперь держит среда:** эта ошибка не проходит, а репро в CI не даёт барьер тихо ослабить. Цена правила = цена инцидента × свежесть памяти: правило через неделю пишется по догадкам.

---

## Шаг 3. Петля в команде

То, что работало для одного человека, ломается на пятерых и десятках агентов: правила начинают противоречить, агенты конкурируют за ресурсы, ошибка одного повторяет другой.

**Действия:**
1. **Общий AGENTS.md.** Правки только через MR. Факт живёт в одном слое. Две одинаковые поправки агенту за неделю — правило в файл, а не третья поправка в чате.
2. **Общее хранилище ошибок.** `./harness.sh project <repo> --team-store`: ошибка одного агента становится барьером для всех.
3. **Зоны.** Red Zone — запрет (B05, B06, B28, B31, B32), Yellow — вопрос человеку (B04, B29, B30, B33), Green — всё остальное.
4. **Права через MCP.** Опасный ресурс (БД, GPU, PII, ядро продукта) агент получает только через MCP-сервер, который знает, что запрещено (`extras/mcp/`).
5. **Аренда ресурсов.** Задачи — `SELECT … FOR UPDATE SKIP LOCKED`, heartbeat с TTL; файлы — аренда с TTL; провайдер LLM — семафор с коротким таймаутом.
6. **ADR — память решений.** Агент сверяет свои пути с `Applies To` принятых ADR; противоречие — стоп до нового ADR. Номер выдаёт гейт, а не память агента (B13).
7. **Спека до кода.** OpenSpec: propose → apply → archive.

**Готово, когда:** номера ADR уникальны, у каждого MR заполнены поля ADR, агенты не конфликтуют за ресурсы.

**Теперь держит среда:** решения команды (ADR), общие ресурсы (аренда), ошибки всех агентов (общее хранилище).

## Шаг 4. Пайплайн проверок

**Путь изменения:** аренда задачи и файлов → работа в своей ветке → `pre-push` и тесты по диффу → гейты (`gates/run-all.sh`: удалённые тесты, заглушки, подавление линтера, lock-файлы, секреты, ADR) → индекс дрейфа архитектуры → MR в `dev` и ревью человека.

**Путь правила:** ошибка на любом шаге → событие → `evolve` → черновик в `error.md` → агент пишет барьер → ревью харнеса (`review/harness-review.md`) → карантинный арбитраж (`review/arbitration.md`) → merge.

**Готово, когда:** нарушение блокирует среда, а не договорённость.

**Теперь держит среда:** дрейф кода от спеки и ADR, ослабление тестов, обрезанный код (`// ... rest of the code`).

## Шаг 5. Замеры: умнеет ли среда

Раз в неделю `./harness.sh dashboard` и `./harness.sh metrics <repo>`.

| Вопрос | Метрика | Хороший тренд |
|---|---|---|
| Агент реже ошибается | ошибки инструментов на 100 вызовов | падает |
| Знает правила и не пытается | срабатывания барьеров на 100 вызовов | падает |
| Ловит новое, а не только старое | новые варианты, пойманные барьерами; барьеры без инцидента | > 0, утечек нет |
| Новые виды ошибок редеют | новые классы инцидентов по неделям | к нулю |
| Ошибку находит машина | доля `Found by: barrier / gate / ci / dashboard` | растёт |
| Дешевле | рубли и токены на сессию | падает |
| Быстрее | активное время сессии | падает при том же объёме |
| Харнес не разбухает | пунктов правил в AGENTS.md при росте кода | плато |
| Работа уходит не на починку | доля коммитов-исправлений | падает |

**Готово, когда:** тренд виден за 4+ недели. Правил больше, а ошибок не меньше — харнес копит противоречия: пора на ревью правил. Барьер, который месяц не срабатывал, но стоит токенов или миллисекунд (`./harness.sh budget`), — кандидат на удаление.

На ArcSpace за 18 недель: доля исправлений упала с ~50% до < 5% при росте потока коммитов в 5 раз, число правил держалось на 11–13 пунктах.

**Теперь держит среда:** решение «стало ли лучше» принимается по цифрам, а не по ощущению.

---

## Шаг 6. Фиксация

**Действия:**
1. Записать окружения и права агента в каждом: локальная машина, оркестрация, CI, прод.
2. Ветки: работа только в `dev`, `main` — прод, через MR `dev` → `main` и ручной деплой.
3. Общие находки — в глобальный слой через MR; барьеры, полезные всем, — в этот набор с атакой в демо.
4. `evolve` — в ежедневный ритм: раз в день или в конце сессии.

**Готово, когда:** новый человек разворачивает процесс по этому файлу без вопросов к автору, а петля крутится без него.
