# Тексты для агентов по ASD-STE100

Агент перечитывает `AGENTS.md`, скиллы и правила на каждой задаче. Каждое лишнее слово в них оплачивается токенами столько раз, сколько агент запускается, а каждая двусмысленная фраза — ошибкой. Поэтому всё, что читает агент, в MAH написано на **Simplified Technical English** — контролируемом языке из стандарта [ASD-STE100 Issue 9](https://www.asd-ste100.org) (авиационная техническая документация, 2025-01-15). Тексты для людей (README, PROCESS.md) остаются на русском.

## Что даёт

Замер на шаблонах этого репозитория: старая русская версия против новой английской по STE. Токенизаторы OpenAI (`tiktoken`) — это оценка: у Claude свой токенизатор, но порядок тот же.

| Файл | Токенизатор | RU | EN-STE | Файл целиком | На одно правило |
|---|---|---|---|---|---|
| Глобальные правила | o200k | 687 ток., 22 правила | 617 ток., 29 правил | −10% | −32% |
| Глобальные правила | cl100k | 992 | 628 | −37% | −52% |
| Правила проекта | o200k | 312 ток., 12 правил | 255 ток., 12 правил | −18% | −18% |
| Правила проекта | cl100k | 411 | 255 | −38% | −38% |

Английская версия длиннее по содержанию (29 правил против 22), но дешевле. Второй эффект важнее: одна инструкция в предложении и одобренные слова убирают двусмысленность — агент реже понимает правило «по-своему».

Замерить свои файлы: `pip install tiktoken`, затем `python metrics/token_count.py`.

## Правила, которые проверяет машина

Гейт `gates/check-ste.py` (барьер B18) проверяет правила, которые можно измерить. Номера — по ASD-STE100 Issue 9, Part 1.

| Правило | Что требует | Как проверяем | Уровень |
|---|---|---|---|
| 5.1 | Инструкция — не больше 20 слов | пункты списков и нумерованные шаги | ошибка |
| 6.3 | Описание — не больше 25 слов | предложения в абзацах | ошибка |
| 6.6 | Абзац — не больше 6 предложений | абзацы | ошибка |
| 4.2 | Без сокращённых форм (don't, it's) | регулярное выражение | ошибка |
| 8.1 | Без точки с запятой | поиск `;` вне кода | ошибка |
| 1.1 | Только одобренные слова | словарь неодобренных слов с заменами (`gates/ste-wordlist.tsv`, 36 частых слов из Part 2) | ошибка |
| 5.2 | Одна инструкция в предложении | «and then», «, then» в инструкции | предупреждение |
| 3.6 | Активный залог | «is/are/was/were/be/been + причастие» | предупреждение |

Подсчёт слов — по правилам 8.5–8.7: текст в скобках, число с единицей измерения и слово через дефис считаются одним словом. Не проверяются: блоки кода, `inline code`, таблицы, заголовки, YAML front matter, ссылки и предложения с кириллицей.

`--strict` превращает предупреждения в ошибки. В CI этого репозитория скиллы и шаблоны проверяются в строгом режиме.

## Правила, которые остаются на ревью

Их нельзя надёжно проверить регулярным выражением, поэтому они в скилле `ste-writing` и в чек-листе ревью:

- 2.1 — составное существительное не длиннее трёх слов («runway light connection», а не «runway light connection resistance calibration»);
- 3.2 — только инфинитив, повелительное наклонение, простые настоящее, прошедшее и будущее время;
- 3.5 — форма на «-ing» только как часть технического термина;
- 1.11 — один термин для одной вещи;
- 5.3 — инструкции в повелительном наклонении;
- 5.5 — примечание даёт информацию, а не инструкцию;
- 9.3 — без фразовых глаголов.

## Словарь

`gates/ste-wordlist.tsv` — 36 слов, которые часто встречаются в промптах и правилах агентов и не одобрены в словаре STE, с одобренной заменой. Примеры:

| Не одобрено | Пишем |
|---|---|
| ensure, verify | make sure |
| utilize, employ | use |
| perform, execute, implement, accomplish | do |
| provide | give |
| obtain, acquire | get |
| modify | change |
| maintain, retain | keep |
| commence, initiate | start |
| terminate | stop |
| whether | if |

Полный словарь — в стандарте (Part 2). Мы не копируем его целиком: стандарт распространяется ASD отдельно, а нам нужна выборка слов, которые реально встречаются в правилах агентов. Добавляйте слова в TSV по мере того, как они появляются в ваших файлах.

## Как писать

```text
Плохо:  Ensure that you utilize the staging database and then run the migration scripts.
        (1.1 ensure, 1.1 utilize, 5.2 две инструкции)
Хорошо: Use the staging database.
        Run the migration scripts.
```

```text
Плохо:  Tests that are skipped by the agent are not allowed.     (3.6 пассив)
Хорошо: Do not skip tests.
```
