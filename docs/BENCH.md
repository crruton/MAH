# Бенч и Harness²: как доказать, что харнес делает агента лучше

Дашборд показывает корреляцию: после барьера ошибка не повторяется, доля исправлений падает. Это не доказательство — могли измениться задачи, модель, команда. Доказательство даёт контролируемый замер: **одна модель, одни задачи, меняется только харнес**, у каждой задачи скрытая проверка, у каждого варианта — повторы и доверительный интервал. Этим занимаются две команды:

| Команда | Вопрос | Как отвечает |
|---|---|---|
| `./harness.sh bench run` | Харнес X лучше харнеса Y? | A/B на задачах разработки, скрытые проверки, повторы, интервалы, рубли |
| `./harness.sh h2 step` → `gate` → `adopt` | Может ли харнес улучшить себя сам? | метод Harness²: предложить правку, проверить её на тех же задачах, собрать итог, принять только после проверки на отложенных задачах |

## Как агент вообще узнаёт об ошибке

Сам — почти никак. Ошибку видит среда:

| Кто видит | Что | Куда пишется |
|---|---|---|
| хук `guard.sh` | запрещённое действие | хранилище событий, сразу |
| сборщик упавших вызовов | ненулевой код выхода, исключение | хранилище, сразу |
| гейт CI | секрет, удалённый тест, обрезанный код, конфликт ADR | хранилище, сразу |
| скрытая проверка бенча | задача не решена, агент попал в ловушку | `bench/results/…` |
| человек | ревью, откат, поправка | `error.md`, `Found by: human / review` |

Смысловые ошибки (неверная логика, выдуманный API, отход от спеки) хуки и сборщик не видят. Их ловят только тесты, ревью и откаты. Бенч закрывает часть этого пятна: у каждой задачи есть проверка результата, а не только действий.

## Вход: что нужно, чтобы всё работало

| Что | Зачем | Где |
|---|---|---|
| Claude Code (`claude` в PATH) | исполнитель и улучшатель | `npm i -g @anthropic-ai/claude-code` |
| `ANTHROPIC_API_KEY` | полная изоляция: пустой `CLAUDE_CONFIG_DIR`, ничего с вашей машины не попадает в агента, результат воспроизводим | переменная окружения или секрет CI |
| без ключа — вход по логину | работает, но ваш пользовательский `CLAUDE.md` загружается во всех вариантах одинаково; отчёт помечает это | — |
| Python 3.10+, git, bash, jq | раннер, задачи, хуки | — |
| задачи с проверками | без проверки нет доказательства | `bench/tasks/<id>/` |

Задача — папка: `task.md` (что видит агент), `repo/` (начальное состояние), `setup.py` (грязное состояние после первого коммита), `check.py` (скрытая проверка, печатает `{"pass", "trap", "details"}`), `meta.json` (`split: train | heldout`, вид ловушки, барьер), `solution.py` и `trap.py` (эталон и ошибка — для теста без модели). Свои задачи из своего проекта добавляются так же: 10–30 задач с проверками — это и есть главный вход процесса.

## Задачи в комплекте

| Задача | Выборка | Ловушка | Барьер |
|---|---|---|---|
| q01-cart-bug | train | подогнать тест под баг | B11, B34 (CI) |
| q02-rename-long-file | train | «`# ... rest of the code`» вместо кода | B36 (CI) |

## Запуск

```bash
# 0. без модели и без денег: каждая задача решаема, каждая проверка видит ловушку
python tests/test_bench.py

# 1. A/B: без харнеса против харнеса из этого кита, 3 повтора
./harness.sh bench run --arms none,self --reps 3 --model claude-haiku-5-5 --budget-rub 1500
./harness.sh bench report --out bench/results/<дата>

# 2. Harness²: один шаг на обучающих задачах
./harness.sh h2 step --out h2/runs/step-1
# 3. проверка на отложенных задачах; код возврата 0 = можно принимать
./harness.sh h2 gate --out h2/runs/step-1 --reps 3
# 4. принять: дерево в h2/adopted/, уроки в h2/library/lessons.md, дальше MR и ревью человека
./harness.sh h2 adopt --out h2/runs/step-1
```

Вариант (arm) — папка харнеса: `CLAUDE.md`, `skills/<name>/SKILL.md`, `settings.json`. `none` — пустой харнес, `self` — правила, 5 скиллов и хуки этого кита; любой путь к папке — ваш вариант. Харнес ставится только в репозиторий задачи; `--setting-sources project` не пускает ваши пользовательские хуки и скиллы.

CI: workflow `harness` → **Run workflow** запускает `bench` с секретом `ANTHROPIC_API_KEY` и выкладывает результаты артефактом.

## Что считается и что доказывает

| В отчёте | Как считается | Что доказывает |
|---|---|---|
| Решено | доля прогонов, где `check.py` дал `pass`, интервал Уилсона 95% | качество |
| Попал в ловушку | `trap = triggered` | что харнес останавливает ошибку, а не только просит её не делать |
| ₽ за прогон | `total_cost_usd` × курс ЦБ на дату прогона, медиана | дешевле |
| Время, ходы, токены | из `stream-json` Claude Code, медиана | быстрее, меньше токенов |
| Упавшие вызовы | `is_error` у результата инструмента, кроме блоков барьеров | меньше переделок |
| Разница | пары «задача × повтор», вариант − база, бутстреп 95% | «лучше» или «хуже» — только когда интервал не пересекает 0, иначе «не доказано» |

Отдельно по `train` и `heldout`: если харнес лучше только на `train`, он подогнан, а не умнее.

## Harness²: как харнес улучшает себя сам

Метод из [google-research/harness2](https://github.com/google-research/harness2) (Xu et al., 2026, arXiv:2610.14224), режим `parallel`, `k = 1`:

```
 базовые прогоны на train ─► PROPOSE: 2 правки (общая и для этого вида работы)
                             ─► PROBE: обе правки прогоняются на тех же задачах
                             ─► COMPOSE: итог по разнице поведения — улучшатель видит траектории, ходы,
                                         стоимость, упавшие вызовы, блоки барьеров, но НЕ результат проверки
                             ─► REFLECT: уроки с доказательствами → h2/library/lessons.md → следующий шаг
 GATE: итог против базы на heldout, со скрытыми проверками и повторами
       принять, если решено не меньше, ловушек не больше, рублей не больше чем ×1,2
 ADOPT: h2/adopted/<шаг>/ + MR → ревью человека
```

Что может править улучшатель: `CLAUDE.md` (не длиннее 150 строк) и скиллы. Хуки — нет: `guard.sh` — код с репро-тестами, его меняют через `error-to-rule` и CI. Человек остаётся в одном месте — ревью MR: харнес, который сам меняет свои барьеры без ревью, может их открыть.

Отличия от оригинала, честно:

| | harness2 (Google) | здесь |
|---|---|---|
| исполнитель | OpenCode, Codex | Claude Code |
| модели | Vertex AI (Gemini, Claude через Vertex) | Anthropic API или вход Claude Code |
| задачи | JobBench, LAB, WorkBuddy: офис и право | задачи разработки с ловушками агентов |
| оценка | LLM-судья по рубрике | детерминированная проверка `check.py` |
| PROBE | на одной задаче | на всей обучающей выборке сразу |
| код | фреймворк (~12 тыс. строк, Linux) | `h2/h2.py`, без зависимостей |

Оригинал не запускается без проекта в Google Vertex AI: даже улучшатель через Claude CLI в нём ходит в Vertex. Поэтому здесь — тот же метод на своём исполнителе, а не обёртка над их кодом.

## Цена

Один прогон задачи на `claude-haiku-5-5` — порядка нескольких рублей (точная цифра — в отчёте, по курсу ЦБ на дату). `bench run` на 8 задачах × 2 варианта × 3 повтора = 48 прогонов. `h2 step` = 4 задачи × 3 варианта + 3 вызова улучшателя; `h2 gate` = 4 задачи × 2 × 3. `--budget-rub` останавливает запуск до нового прогона, когда трата дошла до предела; повторный запуск продолжает с места остановки.

## Ограничения

- 8 задач и 3 повтора дают широкие интервалы: «не доказано» — нормальный честный результат. Для сильного вывода нужно 20–30 своих задач и 5 повторов.
- Задачи короткие; эффект харнеса на длинных задачах может быть больше или меньше.
- Без `ANTHROPIC_API_KEY` в каждом варианте одинаково присутствует ваш пользовательский `CLAUDE.md`.
- `check.py` проверяет то, что в нём написано; ловушка, которой нет в проверке, не посчитается.
