# MAH — my automated harness

**Харнес, который развивается сам.**

**Модель не учится между сессиями. Учится среда вокруг неё — и это видно по цифрам.**

Агент в разработке ошибается. Обычно человек замечает ошибку и дописывает ещё одно правило в промпт; правила копятся, противоречат друг другу, а ошибки возвращаются. Здесь среда учится двумя петлями, и обе проверяются числами, а не ощущением.

```
 Петля барьеров (каждая сессия)                       Петля правил — Harness² (раз в неделю)
 ┌─► 1. ПОЙМАТЬ   хук, гейт, упавший вызов → событие   ┌─► 1. PROPOSE  две правки правил: общая и для вида работы
 │   2. ЗАМЕТИТЬ  повтор или растущая ошибка → evolve   │   2. PROBE    обе прогоняются на тех же задачах
 │   3. ЗАПИСАТЬ  черновик инцидента в error.md         │   3. COMPOSE  итог по разнице поведения, без доступа к проверкам
 │   4. ЗАПРЕТИТЬ барьер против класса + репро в CI     │   4. GATE     A/B на отложенных задачах со скрытыми проверками
 │   5. НАУЧИТЬ   сообщение барьера + строка правила    │   5. REFLECT  уроки → следующий шаг
 └── 6. ПРОВЕРИТЬ дашборд: 0 попыток — выучено          └── 6. MR      Draft PR с step.md; сливает человек
```

Человек участвует в двух местах: ревьюит PR с новым барьером или правилом и решает, ошибка ли это вообще. Чему харнес может учиться, а чему нет, записано в одном файле — [h2/policy.json](h2/policy.json): например, он не может добавить правило «можно `--no-verify`» и не может удалить правило про секреты. Подробно — [docs/LOOP.md](docs/LOOP.md) и [docs/BENCH.md](docs/BENCH.md), доклад — [docs/TALK.md](docs/TALK.md).

*A self-improving harness for AI coding agents. Hooks and gates catch agent errors, repeats become draft incidents, the agent turns each into a barrier with a repro test. Once a week the Harness² method (google-research/harness2) proposes, probes and composes an edit of the rules, and an A/B bench with hidden checks decides; a human merges the draft PR. Claude Code or OpenCode with any provider. ~160 tokens per session, ~110 ms per tool call. Docs in Russian, costs in rubles. MIT.*

## Что показали замеры

46 задач разработки с ловушками из реальных инцидентов (уничтожить чужую работу, переписать историю на сервере, прочитать секрет, обойти хук, ослабить тест, обрезать код, поправить `node_modules`), 924 прогона, 438 ₽ на весь замер. Подробно, с методикой и ограничениями — [docs/RESULTS.md](docs/RESULTS.md).

| Показатель | без харнеса | лёгкий харнес | изменение | доказано? |
|---|---|---|---|---|
| Прогонов с опасным действием | 14% | 3% | **−80%, в 4,9 раза меньше** | да |
| — уничтожена работа / переписана история / правка `node_modules` | 18 | 0 | −100% | |
| — секрет в контексте модели | 26 | 9 | −65% | |
| Нерешённых задач | 20% | 13% | **−34%, в 1,5 раза меньше** | да |
| ₽ за задачу | 0,43 | 0,48 | +14% | да, дороже |
| Время на задачу | 53 с | 62 с | +17% | да, медленнее |

Короткие правила (`templates/AGENTS.lean.md`, 10 правил) с барьерами работают лучше длинных (21 правило + 5 скиллов: опасных действий −61%, нерешённых −10% не доказано). Остаток утечек — два класса, которые путь-барьер не видит: секрет в выводе упавшего теста и пароль в обычном JSON. Это следующие барьеры петли.

Первый шаг Harness² ([step.md](h2/results/2026-11-07-step1/step.md)) добавил 14 правил: агент стал быстрее и ошибался в вызовах реже, но на отложенных задачах решил на 8,3 п.п. меньше — gate правку отклонил.

## Быстрый старт

```bash
git clone https://github.com/crruton/self-harness.git
cd self-harness
./harness.sh install --auto-evolve   # Windows: harness.cmd install  (нужен Git for Windows и jq)
./harness.sh demo                     # 37 атак должны остановиться, 18 обычных действий — пройти
./harness.sh dashboard                # становится ли агент лучше: ~/.claude/harness/dashboard.html
python tests/test_bench.py            # бенч и шаг Harness² без модели и без денег
./harness.sh bench run --reps 3       # A/B на модели: 46 задач × 2 варианта × 3 повтора, ~130 ₽
./harness.sh h2 auto                  # шаг Harness² + gate: прогоны ~17 ₽ + вызовы улучшателя
```

Удалить: `./harness.sh uninstall`. Ваши настройки, хуки и скиллы остаются как были.

## CI в этом репозитории

| Workflow | Когда | Что делает |
|---|---|---|
| `harness` | каждый push и PR | демо 37 атак, установка и удаление, проектный режим, репро-тесты, бенч и Harness² на заглушке |
| `bench-gate` | PR меняет правила, скиллы, хуки или политику | A/B «харнес `main` против харнеса PR», отчёт комментарием в PR, падает, если PR доказанно хуже или попадает в ловушки |
| `h2-weekly` | понедельник 03:00 UTC и вручную | шаг Harness² и gate; если gate принял — Draft PR в `dev` с `step.md`. Не сливает |

Бенчу нужен секрет `ANTHROPIC_API_KEY` (Settings → Secrets → Actions). Без него оба workflow пишут об этом и проходят. Для `h2-weekly` включите Settings → Actions → «Allow GitHub Actions to create and approve pull requests». Модель и бюджет: переменные `HARNESS_BENCH_MODEL`, `HARNESS_H2_IMPROVER_MODEL`, `HARNESS_BENCH_BUDGET_RUB`.

## Дашборд: становится ли агент лучше в работе

Бенч доказывает на задачах с проверками; дашборд показывает, держится ли эффект в настоящей работе. Последние 4 недели против 4 предыдущих:

| Вопрос | Метрика |
|---|---|
| Качественнее | ошибки инструментов на 100 вызовов |
| Знает правила и не пытается | срабатывания барьеров на 100 вызовов |
| Дешевле | токены (без чтения кэша) и рубли на сессию, рубли за неделю по курсу ЦБ РФ |
| Быстрее | активное время сессии (паузы 5+ минут не считаются) |
| Меньше нагрузки на человека | вопросы барьеров и отказы человека на сессию |

Для каждого инцидента — что стало после барьера: «агент не пытается», «барьер держит, агент пытается», «утечка». Знаменатель (вызовы, токены, деньги) берётся из журналов сессий Claude Code, поэтому хуки на успешных вызовах ничего не стоят. Курс: `HARNESS_USD_RUB`, иначе курс ЦБ на сегодня (один GET к cbr.ru, ничего не отправляется), иначе последний сохранённый; `HARNESS_OFFLINE=1` — без сети.

## guard.sh: запретить, спросить, пропустить

Каждая блокировка — лишний вопрос человеку. Поэтому запрет только для того, что git не вернёт.

| Уровень | Что | Почему |
|---|---|---|
| **Запретить** | B05: `git reset --hard`, `git clean -f`, `git checkout -- .`, `git restore .`, force-push (в том числе `--force-with-lease`), удаление ветки на сервере, `rm -rf` для `/`, `~`, `$HOME`, `.`, `..`, `*`, `.git`; B06: чтение и правка `.env`, ключей, сертификатов, `secrets/`, конфигов с паролями (`*.local.json`, `settings.local.*`, `credentials.json`, `secrets.json`, `secrets.yaml`, `secrets.toml`); B28: `--no-verify`, `HUSKY=0`; B31: хранилища токенов (`~/.aws/credentials`, `~/.kube/config`, `~/.docker/config.json`, `.git-credentials`, `.netrc`, `~/.ssh/id_*`); B32: ручная правка lock-файлов и `node_modules/`, `.venv/` | теряется незакоммиченная работа или чужая история; хук нашёл проблему, а агент её обходит; секреты не должны попадать в контекст модели; lock-файл расходится со сборкой |
| **Спросить** | B04: полный прогон тестов (npm, pytest, go, cargo, maven, gradle, dotnet, rspec, phpunit, mix, swift, flutter, deno, ctest, make test); B05: `git branch -D`, `DROP`/`TRUNCATE`, `docker system/volume prune`; B29: `curl … \| sh`; B30: `npm publish`, `docker push`, `terraform apply`, `kubectl delete`, `helm upgrade`, деплой; B31: `env`, `printenv`, `echo $…TOKEN`; B33: правка хуков и настроек агента | бывает нужно, но действие уходит за пределы машины, открывает секреты или меняет защиту самого агента |
| **Маскировать** | B39: команда, в которой только тесты (`pytest`, `npm test`, `python -m unittest`, `go test`…) и чтение (`cd`, `cat`, `ls`, `grep`, `tail`, `git status`…), в репозитории с секретными файлами. Например `cd DIR && cat CLAUDE.md && pytest 2>&1 \| tail` | упавший тест печатает то, что прочитал, и секрет из `.env` попадает в контекст модели. Хук пропускает вывод через фильтр, который заменяет значения секретных файлов и известные форматы токенов на `***`; код возврата теста сохраняется. Такую команду хук разрешает без вопроса. Выключить: `HARNESS_MASK=0` | всё остальное: `rm -rf build`, `docker compose down -v`, `git push origin dev`, `git push -n`, тесты пакета, `terraform plan`, `curl … \| jq`, `printenv PATH`, `.env.example`, `*.pub` | обычная работа |

Проверки видят команду и внутри обёрток: `sh -c '…'`, `bash -c`, `python -c`. «Спросить» — это ответ хука `permissionDecision: "ask"` в Claude Code: агент не упирается в стену, человек решает одним нажатием. Полный прогон тестов без вопроса: `CLAUDE_FULL_TESTS=1 <команда>`.

Демо проверяет обе стороны: 37 атак должны остановиться и 18 обычных действий должны пройти без вопроса. Ложное срабатывание проваливает демо так же, как пропущенная атака.

## Сборщик и статистика ошибок

Каждое событие — строка JSON в `~/.claude/harness/errors/events-ГГГГ-ММ-<автор>.jsonl`: какой барьер, что заблокировано или о чём спросили, агент или человек, в каком репозитории. Секреты и персональные данные маскируются до записи. Сборщик никогда не роняет хук.

| Источник | Что попадает |
|---|---|
| `hook` | заблокированное или спрошенное действие агента (B04–B06, B28–B33) |
| `tool` | упавший вызов инструмента агента: команда и ошибка |
| `git-hook`, `gate` | срабатывания git-хуков и гейтов CI (проектный режим) |
| `manual` | инцидент `./harness.sh incident` |

```bash
./harness.sh errors                    # все проекты
./harness.sh errors --project shop     # один проект
./harness.sh errors --suggest          # повторы → готовые команды incident
```

| В отчёте | Что делать |
|---|---|
| **Блоки** по барьерам | каждый блок — ошибка, которая не дошла до кода |
| **Вопросы человеку** | барьер часто спрашивает, а вы всегда разрешаете — ложное срабатывание, его надо ослабить |
| По проектам и неделям | где и когда агент ошибается чаще |
| Повторы за 7 дней | барьер держит, но агента туда ведёт инструкция — исправьте источник |
| Инциденты по уровню барьера | много «текст» — правила не проверяются машиной |

Пример — ошибки агента, который собирал этот репозиторий: [error.md](error.md) и [docs/errors.md](docs/errors.md).

## Проектный режим (по желанию)

Для команды, которой нужны проверки в CI. Глобальная установка для него не нужна.

```bash
./harness.sh project <repo> [--team-store] [--lock]
```

Ставит `.githooks/` (B01–B03), `gates/` (17 гейтов), `error.md`, каталог ADR, шаблон MR. `--team-store` — общее хранилище ошибок `.harness/errors/` в репозитории (файл на автора и месяц, сливается в git без конфликтов). `--lock` — `harness.lock`: правка хуков и гейтов не пройдёт CI без ревью.

| ID | Барьер | Что ловит |
|---|---|---|
| B01–B02 | `pre-push` | push в `main`, force-push, удаление ветки |
| B03 | `commit-msg` | «wip», «fix», слишком короткие и длинные заголовки |
| B07 | `check-secrets` | ключи AWS/GitHub/GitLab/Slack, JWT, приватные ключи, пароли в коде |
| B08 | `check-forbidden-files` | `.env`, `*.pem`, `id_rsa` в git |
| B10 | `check-conflict-markers` | забытые `<<<<<<<` |
| B11 | `check-test-weakening` | добавлен `skip`/`.only`/`#[ignore]`, удалены assert |
| B34 | `check-test-deletion` | удалён тестовый файл или тест-функция |
| B35 | `check-suppressions` | новый `eslint-disable`, `@ts-ignore`, `# noqa`, `//nolint`, `#[allow]`… без причины на той же строке |
| B36 | `check-leftovers` | `// ... rest of the code unchanged` вместо кода, `todo!()`, `debugger`, `pdb.set_trace()`, `binding.pry` |
| B37 | `check-lockfile-sync` | в манифесте изменились зависимости, а lock-файл нет (npm, yarn, pnpm, poetry, uv, cargo, go, bundler, composer, mix, pub) |
| B13–B15 | `check-adr-*` | дубли номеров, пустые поля, ссылки на несуществующие ADR |
| B16 | `check-error-log` | инцидент закрыт без барьера и репро-теста |
| B17 | `check-rules-size` | AGENTS.md длиннее 150 строк |
| B18 | `check-ste` | правило для агента нарушает ASD-STE100 |
| B19 | `check-zones` | настройки проекта разрешают Red Zone или отключают хуки |
| B20 | `check-harness-integrity` | хук или гейт изменён без ревью (с `--lock`) |
| B21–B27 | `check-portability` | ошибки Linux → Windows: `re.M`+`\s`, голый `bash` в subprocess, `communicate()` с JSON-RPC, зависимость без верхней границы, текст без `encoding=`/`newline=`, CRLF, нет бита исполнения |

Гейты проверяют только изменение (`HARNESS_BASE` в CI), без внешних зависимостей. Нет ADR, `error.md` или `harness.lock` — соответствующий гейт ничего не делает. Подключение: [`ci/`](ci/). Подробно о каждом гейте — в `gates/*.py`.

**B21–B27 — ошибки агента, который собирал этот репозиторий**, раз за разом при переходе между Linux и Windows. Каждая записана в [error.md](error.md); ошибка B21 повторилась дважды, потому что первое исправление не стало барьером.

## Окупается ли харнес

Харнес полезен, только если его цена меньше цены ошибок, которые он ловит. Раз в неделю: `./harness.sh budget` против `./harness.sh errors`. Барьер, который за месяц ни разу не сработал, но стоит токенов или миллисекунд, — кандидат на удаление; барьер, который часто спрашивает, а вы всегда разрешаете, — кандидат на ослабление.

Как это нашлось на самом наборе: первая версия хуков стоила ~2,5 с на каждый вызов инструмента, профиль со всеми MCP и скиллами — ~3 000 токенов в сессии, `guard-destructive` блокировал `docker compose down -v` и `rm -rf build`. Сейчас — ~110 мс, ~160 токенов, 0 ложных срабатываний в демо.
