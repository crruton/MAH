# agent-harness-core

Процесс, в котором ИИ-агенты работают над проектом и сами держат границы его дрейфа. Здесь всё, что нужно, чтобы взять этот процесс, развернуть у себя за 10 минут и попробовать.

*A process kit for AI coding agents: layered context, Red/Yellow/Green zones, hooks, gates, ADR memory, an error log that turns incidents into rules, harness review methods and weekly convergence metrics. Docs are in Russian.*

Харнес — это то, что мы забрали у агента: не просьба в промпте, а исполняемый запрет в среде. Каждое забранное право — один пойманный инцидент.

## Процесс за 6 шагов

| # | Шаг | Что делаем | Артефакт | Готово, когда |
|---|---|---|---|---|
| 1 | Базовая линия | Слои контекста, зоны, метрики-границы до первой строки кода | `AGENTS.md`, `zones/` | Агент стартует с правилами, а метрики считаются |
| 2 | Ошибка → правило | Каждая ошибка агента за 24 ч становится барьером и тестом | `error.md`, `rules/` | У инцидента есть барьер и репро-тест |
| 3 | Командные границы | Общий AGENTS.md через MR, права через MCP, аренда ресурсов, ADR, спеки | `docs/adr/`, `mcp/` | Решения и номера не конфликтуют |
| 4 | Пайплайн проверок | Хуки и гейты на каждом шаге, ревью правок харнеса | `hooks/`, `gates/`, `review/` | Нарушение блокирует среда, а не договорённость |
| 5 | Замеры | Еженедельные метрики сходимости харнеса | `metrics/convergence.py` | Правила не разбухают, доля исправлений падает |
| 6 | Фиксация | Процесс и окружения записаны, ветки dev/main | `PROCESS.md` | Новый человек разворачивает процесс сам |

Подробно, с входами и выходами каждого шага, — в [PROCESS.md](PROCESS.md).

## Попробовать за 2 минуты

```bash
git clone <url этого репозитория> agent-harness-core
cd agent-harness-core
bash try-it.sh
```

`try-it.sh` создаёт временный репозиторий, ставит в него харнес и показывает пять барьеров в работе:

1. `pre-push` не даёт запушить в `main`.
2. `guard-tests.sh` блокирует полный прогон тестов агентом.
3. `check-adr-numbers.sh` ловит два ADR с одним номером (наш инцидент ADR-044).
4. `check-error-log.py` не даёт закрыть инцидент без барьера и репро-теста.
5. `check-rules-size.sh` не даёт AGENTS.md разрастись больше 150 строк.

## Поставить в свой проект

```bash
bash install.sh /path/to/your/repo
```

Скрипт копирует шаблоны, не перезаписывая существующие файлы, подключает git-хуки и печатает, что заполнить руками. Дальше — шаг 1 в [PROCESS.md](PROCESS.md).

Требования: git, bash, Python 3.10+, jq (для хука Claude Code). Работает с Claude Code и OpenCode; правила — обычный Markdown, переносятся в любой агент.

## Что внутри

| Каталог | Что там |
|---|---|
| `templates/` | AGENTS.md глобальный и проектный, шаблон и индекс ADR, `error.md`, шаблон MR, CHANGELOG |
| `zones/` | Red / Yellow / Green: настройки прав для Claude Code и OpenCode |
| `hooks/` | `pre-push` (запрет push в main), `guard-tests.sh` (запрет полного прогона тестов агентом) |
| `gates/` | Проверки для CI: уникальность номеров ADR, полнота `error.md`, размер AGENTS.md |
| `review/` | Как принимать правку харнеса: методы ревью, взятые из harness2, и карантинный арбитраж |
| `mcp/` | Паттерн «права через MCP» и пример сервера аренды тестовой среды |
| `metrics/` | `convergence.py`: метрики сходимости харнеса по истории git |
| `loadtest/` | Шаблон нагрузочного теста k6 и изолированного стенда |
| `.github/workflows/` | Те же гейты в CI этого репозитория |

## Откуда это

Процесс вырос из двух проектов: соло-этап на SIP-платформе (10 скиллов, 10 MCP-серверов) и командный этап на ArcSpace (5 инженеров, 37 ролей агентов, 18 недель истории). Доклад: «Харнес, который написал сам себя», HighLoad++ 2026.
